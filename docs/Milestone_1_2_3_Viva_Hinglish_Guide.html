Hamare Project ki 4 Sabse Badi Khasiyat (Core USPs)

  1. AI Symptom Triage: Mareez ko apni bhasha me symptoms likhne hain, AI turant samajh leta hai.
  2. Emergency Bypass: Agar patient ko Heart Attack ya Stroke ke symptoms hain (jaise chest pain, slurred speech), toh routine booking rok kar turant Emergency Red Alert deta hai.

3. Milestone 1 Detail: Existing Systems vs Hamara System

  • Practo / Zocdoc: Doctor directory achhi hai, booking bhi hoti hai, par AI Symptom Checker nahi hai. Patient ko khud guess karna padta hai ki kis specialist ke paas jaaye.
  • Ada Health / Buoy Health: AI symptom checker bohot achha hai, par Doctor appointment booking nahi hai. Diagnosis dekh kar user ko doosre app me jaana padta hai.
  • Hamara System: Dono ko ek single platform me seamlessly jod diya hai!

4. Milestone 2 Detail: Dataset, Preprocessing & AI Engine

4.1 Data Cleaning Pipeline (6 Steps)

[Raw Clinical Data / User Input Text]
       │
       ▼  Step 1: UTF-8 Encoding Sanitization
       ▼  Step 2: Null / Empty Records Removal
       ▼  Step 3: Deduplication (Duplicate symptoms hataye)
       ▼  Step 4: Clinical NLP Tokenization (Lowercase + Regex \w+)
       ▼  Step 5: Medical Synonym Harmonization ("dyspnea" → "shortness of breath")
       ▼  Step 6: Urgency Stratification (Emergency / High / Medium / Low)
       │
[Clean Knowledge Base in backend/data/symptom_specialist_dataset.csv]

4.2 AI Algorithm Kaise Kaam Karta Hai? (Two-Tier Engine)

Tier 1: Emergency Red-Flag Classifier (Pehle Check)
Emergency keywords: ["chest pain", "shortness of breath", "slurred speech", "numbness in face", "arm pain", "stroke", "heart attack", "unconscious", "difficulty breathing"].
Agar user inme se kuch bhi bolta hai → System turant EMERGENCY RED ALERT deta hai aur normal booking cancel karke 112/108 helpline call karne ko kehta hai.
Tier 2: Tokenized Jaccard Similarity Matcher (Specialist Recommendation)
Agar emergency nahi hai, toh user input tokens aur dataset symptoms ke tokens ka overlap (Jaccard Similarity) nikalte hain: $$\text{Confidence} = \min\left(0.60 + (\text{Similarity} \times 0.35),\, 0.95\right)$$ Safe Default Routing: Agar similarity 15% se kam ho, toh safe side rehkar General Physician ko recommend kiya jaata hai (70% confidence).

5.2 Project ke 8 Subsystem Modules

1. Auth & Identity Service

Google OAuth 2.0 GIS token verification, OTP verification, Bcrypt password hashing, JWT session tokens.

2. AI Chatbot Drawer

Interactive drawer jo right side se slide-in hota hai, conversational symptom intake ke liye.

3. Clinical Assessment Engine

User ke text se disease aur urgency calculate karta hai, emergency detect karta hai.

4. Doctor Recommendation Service

Diagnosed specialty ke hisab se verified doctors filter karke show karta hai.

5. Doctor Schedule Management

30-minute ke consultation slots maintain karta hai, real-time availability check karta hai.

6. Appointment Booking Engine

Atomic transaction booking karta hai taaki double-booking kabhi na ho sake.

7. Patient Health Records

Patient ki past booking history, reported symptoms aur AI diagnosis save rehta hai.

8. Doctor Clinical Dashboard

Doctor ko unke daily patients ki list aur AI-generated pre-consultation summary dikhata hai.

5.3 Double-Booking Prevention Kaise Hoti Hai?

Database me (doctor_id, date, slot) par Unique Constraint laga hai aur booking logic Atomic Transaction me chalti hai. Agar do patients ek hi waqt par same slot click karein, toh pehle wale ka book ho jaata hai aur doosre ko backend se HTTP 409 Conflict error milta hai, jisse UI me wo slot instantly disable ho jaata hai.

6. Top 10 Viva Questions & Answers (Examiner ke Saamne Bolne ke Liye)

Q1: Aapke project ka main objective kya hai?
Answer: Hamara main objective hai ek aisa intelligent healthcare system banana jo patient ke symptoms sunkar AI ki madad se bimari aur emergency detect kare, sahi specialist doctor recommend kare, real-time me bina slot conflict ke booking karaye, aur doctor ko consultation se pehle ek structured clinical summary provide kare.
Q2: Milestone 1, Milestone 2 aur Milestone 3 me kya difference hai?
Answer:
  • Milestone 1: Market study (Practo vs Ada Health), gap identification, aur Functional / Non-Functional Requirements define kiye.
  • Milestone 2: Medical datasets collect kiye, 6-stage data preprocessing ki, aur 2-Tier AI Triage recommendation engine code kiya.
  • Milestone 3: Full system architecture banayi, 8 functional modules design kiye, relational ER database banaya, aur Google OAuth 2.0 / JWT security integrate ki.
Q3: Backend me Django ya Flask ke badle FastAPI kyu use kiya?
Answer: FastAPI modern asynchronous framework hai jo Python ke asyncio par chalta hai. Ye Flask aur Django se 3x fast hai, isme Pydantic ki vajah se automatic request validation milti hai, aur API test karne ke liye Swagger UI documentation automatically ban jaati hai.
Q4: Agar patient ko heart attack ke symptoms hain toh AI kya karega?
Answer: Hamara Tier 1 Emergency Classifier emergency keywords (jaise chest pain, left arm pain, breathlessness) ko detect karte hi normal clinic booking ko bypass kar deta hai aur screen par Emergency Red Alert dikhakar patient ko turant 112/108 helpline ya nearest hospital ER jaane ka instruction deta hai.
Q5: Agar patient ke symptoms kisi bhi specialist se match na karein toh kya hoga?
Answer: System me ek Safe Default Fallback mechanism hai. Agar similarity score threshold (≤ 15%) se kam rehta hai, toh AI patient ko safely General Physician (Internal Medicine) recommend karta hai, jo standard medical protocol hai.
Q6: Google Sign-In authentication kaise kaam karta hai?
Answer: Hum Google Identity Services (GIS) use karte hain. User jab Google button par click karta hai, toh Google frontend ko ek signed ID Token deta hai. Backend is token ko Google ke servers se verify karta hai, user ka profile save karta hai aur secure JWT session token return karta hai.
Q7: AI ke medical suggestions me legal ya safety risk ko kaise handle kiya hai?
Answer:
  1. Har assessment ke saath statutory disclaimer aata hai ki ye preliminary AI triage hai, final diagnosis nahi.
  2. Doctor-in-the-Loop: AI sirf doctor ke liye pre-consultation summary draft karta hai, final check aur prescription doctor hi karta hai.
  3. Critical emergency me instant ER redirect hota hai.
Q8: Doctor ko is system se kya fayda hota hai?
Answer: Doctor ko unke dashboard par har patient ka pre-consultation AI summary milta hai jisme reported symptoms, duration aur preliminary diagnosis pehle se likha hota hai. Isse doctor ka OPD me 5-10 minute ka repetitive time bachta hai aur wo seedha treatment par focus kar sakte hain.
