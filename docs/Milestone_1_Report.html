Milestone 1 Study: Existing Healthcare & AI Chatbot Analysis

In recent years, digital health platforms have transformed patient care access. However, a comprehensive analysis of existing healthcare platforms reveals a structural divide: traditional booking platforms focus purely on calendar scheduling without diagnostic guidance, whereas advanced AI diagnostic chatbots operate in isolation without appointment integration.

1.1 Comparative Matrix of Existing Systems

Platform Category Core Capabilities AI / LLM Level Key Gaps & Limitations
Practo Booking Engine Doctor search, clinic directory, online consultation & slot booking. Low (Keyword Search) Patients must self-diagnose and select specialist; no preliminary AI triage.
Zocdoc Doctor Discovery Location-based doctor discovery, insurance filter, real-time slots. Low (Rule Search) No symptom checker; requires patient to know their exact medical condition.
Ada Health AI Symptom Checker Probabilistic disease assessment, risk factors, triage report. High (Bayesian Network) Does not offer appointment booking or direct doctor scheduling.
Babylon Health Telehealth AI AI symptom assessment chatbot, virtual consultations, medical records. High (NLP & Expert AI) High operational complexity, restricted clinic network integration.
Buoy Health Triage Navigator Interactive triage questionnaire, level of care routing (ER vs Urgent). Moderate-High (ML) External referral links are fragmented; lacks unified booking database.

1.2 Major Gaps Identified

Triage & Booking Disconnect
Symptom evaluation platforms (Ada) and doctor booking portals (Practo) run independently, forcing users to switch apps manually.
Patient Self-Diagnosis Burden
Patients frequently select incorrect specialties (e.g. visiting Orthopedics for rheumatic joint pain), leading to wasted consultations.
Lack of Emergency Triage
Standard booking platforms lack instant detection of acute emergency symptoms like heart attacks or strokes, delaying urgent care.
Doctor Context Blindness
Doctors receive no prior structured summary of patient symptoms before consultation, spending valuable time on basic intake.

Problem Statement & System Objectives

PROBLEM STATEMENT
"Current healthcare scheduling portals require patients to self-diagnose and select medical specialists without clinical guidance, while AI symptom checkers operate in isolation without offering direct appointment booking. There is a critical need for an integrated system that combines AI-driven symptom assessment, automated doctor-specialty recommendation, emergency risk filtering, real-time slot scheduling, and structured clinical summaries for doctors."

Core System Objectives

  • Intelligent Symptom Triage: Provide a 24/7 AI-powered conversational chatbot to collect patient symptoms, duration, and severity using natural language processing (NLP).
  • Automated Doctor-Specialty Mapping: Map patient symptoms algorithmically to appropriate medical specializations (Cardiology, Dermatology, Neurology, etc.).
  • Emergency Risk Detection: Instantly detect critical life-threatening symptoms and alert patients to seek emergency care (ER) immediately.
  • Seamless Slot Booking: Enable real-time calendar slot reservation with verified doctors based on specialization, rating, and location.
  • Doctor Clinical Dashboard: Generate automated pre-consultation AI clinical summaries for doctors to optimize consultation time.

Technology Stack

The system is designed with a modern, decoupled architecture separating the client interface, API gateway, AI recommendation logic, and data layer.

Frontend Stack
  • Framework: React.js 18 + Vite
  • UI Design: Modern CSS3, Glassmorphism, CSS Variables
  • Icons & Components: Lucide-React Icons
  • HTTP Client: Fetch API / Axios
Backend Stack
  • Runtime: Python 3.14
  • Framework: FastAPI (Asynchronous REST API)
  • Server: Uvicorn ASGI Server
  • Validation: Pydantic Schemas
AI Engine & Algorithms
  • Emergency Classifier: High-risk keyword matching
  • Symptom Matcher: Set Overlap & TF-IDF similarity matcher
  • Knowledge Base: Medical dataset mapping symptoms to disease & specialty
Database & Architecture
  • Dataset Storage: CSV / JSON Medical Mapping
  • Data Models: In-Memory DB (Milestone 1) -> SQLite / PostgreSQL (Milestone 3)
  • Security: CORS middleware, input sanitization
