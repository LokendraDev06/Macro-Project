Executive Summary & Milestone 4 Scope

Milestone 4 marks the successful engineering and integration of the core intelligent features of the AI-Based Patient Appointment System. Transitioning from the architectural specifications established in Milestone 3, this milestone delivers a complete, interactive conversational triage chatbot, an algorithmic doctor recommendation pipeline, and a real-time appointment booking and slot-locking engine.

The developed system allows patients to describe symptoms in natural language, automatically filters life-threatening clinical emergencies, determines the most appropriate medical discipline, retrieves available specialists, and commits verified calendar bookings without double-booking collisions.

AI Health Chatbot Engineering & Conversational Flow

The AI Health Chatbot is implemented as a reactive slide-out drawer (ChatbotDrawer.jsx) communicating asynchronously with the FastAPI backend endpoint (POST /api/chat/assess).

Interactive Conversational Dialogue Sample

I have had severe redness, itching, and dry flaky patches across my neck and arms for 4 days.
Based on your symptoms, our preliminary AI assessment suggests a possible match for Eczema / Contact Dermatitis (Mild / Moderate severity). We recommend scheduling an appointment with a Dermatologist.

📌 Note: This is a preliminary assessment. Please consult a qualified doctor for diagnosis and treatment.

Chatbot Capabilities & UI Features

  • Natural Language Input: Accepts unstructured patient descriptions without requiring medical jargon.
  • Interactive Quick Prompts: Pre-built symptom chips for common patient presentations.
  • Visual Severity Indicators: Color-coded badges indicating Mild, Moderate, or Critical states.
  • Direct Specialty Routing CTA: Generates a direct "View Recommended Doctors" button that instantly filters the provider directory.

Symptom Assessment Engine & Emergency Triage Logic

The underlying assessment logic (ai_engine.py) executes a rigorous two-tier clinical evaluation pipeline:

PATIENT SYMPTOM INPUT | v +------------------------------------+ | TIER 1: EMERGENCY CLASSIFIER | | Matches critical clinical tokens: | | - "chest pain", "shortness of | | breath", "slurred speech", | | - "stroke", "severe bleeding" | +------------------------------------+ / \ [TRIGGERED] [NOT TRIGGERED] / \ +---------------------------+ +------------------------------------+ | URGENT SAFETY OVERRIDE | | TIER 2: SYMPTOM-DISEASE MATCHER | | - Severity: CRITICAL | | - Tokenize and remove stopwords | | - Specialization: ER | | - Vector token overlap calculation | | - Direct to Hospital / 911| | - Knowledge base CSV lookup | +---------------------------+ +------------------------------------+ | v +------------------------------------+ | OUTPUT PRELIMINARY ASSESSMENT | | - Matched Health Condition | | - Recommended Doctor Specialty | | - Clinical Summary for Attending MD| +------------------------------------+

Token Overlap & Confidence Formulations

When evaluating non-emergency symptoms against the curated knowledge base (symptom_specialist_dataset.csv), the engine computes normalized intersection scores:

Score = |Tokens(user) ∩ Tokens(condition)| / max(|Tokens(condition)|, 1)
Confidence = min(round(0.60 + (Score × 0.35), 2), 0.95)

Appointment Scheduling & Slot Locking Engine

The booking module (AppointmentModal.jsx and POST /api/appointments/book) executes a transactional reservation sequence:

1. Calendar & Slot Selection
Patients choose from validated future consultation dates. The UI dynamically populates available slots. If a slot has already been committed, it is locked and disabled to eliminate booking races.
2. Clinical Intake & AI Payload Binding
The booking payload encapsulates the patient's verified contact info, reported symptoms, and the pre-computed AI triage summary (e.g. "Patient reports chest tightness. Preliminary Assessment: Angina. Recommended: Cardiologist").
3. Atomic Transaction Execution
The backend validates the doctor ID and slot availability before committing the appointment record. A unique identifier (e.g. apt-1002) is generated with status Confirmed.
4. Real-Time Provider & Patient Sync
Upon successful creation, the appointment appears immediately in both the Patient Health Portal and the Doctor's Clinical Review Dashboard.
TRANSACTION INTEGRITY VERIFICATION
Testing confirmed that invalid slots return an immediate 400 Bad Request response. No orphaned records or duplicate bookings can occur during high-concurrency requests.
